    cin >> a >> b >> c;

WHEN: Fixed number of whitespace-separated values.

INPUT: 10 20 30

Also works if formatted as:

    10

3. N VALUES, BUT YOU DON’T NEED TO STORE THEM

    int n;
    cin >> n;

    for (int i = 0; i < n; ++i) {
        int x;
        cin >> x;

        // process x
    }

WHEN: Only one-pass processing is required.

BENEFIT: O(1) extra memory instead of O(N).

4. READ UNTIL EOF

    int x;

    while (cin >> x) {
        // process x
    }

WHEN: The problem does NOT provide N/T and input continues until EOF.

INPUT: 1 2 3 4 5 6

Reads: 1 2 3 4 5 6

IMPORTANT: Do not use getline() merely because the values appear on one
line. cin >> naturally crosses line boundaries.

6. READ A WHOLE LINE

    string s;
    getline(cin, s);

WHEN: Spaces are part of the data and the entire line matters.

INPUT: hello competitive programming

RESULT: s == “hello competitive programming”

Do NOT use cin >> s here; it would only read “hello”.

7. THE cin >> + getline() TRAP

BAD / SURPRISING:

    int n;
    cin >> n;

    string s;
    getline(cin, s);

INPUT: 5 hello world

RESULT: n = 5 s = “”

WHY: cin >> n leaves the newline in the input stream. getline()
immediately consumes that newline.

FIX:

    int n;
    cin >> n;
    cin.ignore(numeric_limits<streamsize>::max(), '\n');

    string s;
    getline(cin, s);

WHEN: You genuinely need to switch from token extraction to line
extraction.

8. DISCARD ONE CHARACTER / NEWLINE

    cin.ignore();

WHEN: You KNOW exactly one unwanted character remains.

Example: cin >> n; cin.ignore(); getline(cin, s);

PREFERRED GENERAL FORM:

    cin.ignore(numeric_limits<streamsize>::max(), '\n');

WHEN: You want to discard everything through the next newline.

BEST PRACTICE: Use the long form when input before the newline might
contain more than one character.

9. getline() + stringstream

    string line;
    getline(cin, line);

    stringstream ss(line);

    int x;
    while (ss >> x) {
        // process x
    }

WHEN: The LINE itself matters and then you want to parse tokens inside
it.

GOOD USE CASES: - variable-length records, one record per line - each
line has a different number of values - need to preserve line
boundaries - custom line-oriented input format

LESS GOOD: Normal “N integers follow” CP input.

For normal numeric input, simply use cin >> x.

    string line;

    string name;

    ss >> name >> age >> score;

WHEN: One line contains several different token types.

INPUT: Alice 21 98.5

11. READ N LINES

    int n;
    cin >> n;
    cin.ignore(numeric_limits<streamsize>::max(), '\n');

    for (int i = 0; i < n; ++i) {
        string s;
        getline(cin, s);
        // process s
    }

WHEN: The next N records are actual lines, potentially containing
spaces.

If each line is just one word/token: use cin >> s instead.

12. MATRIX / GRID OF INTEGERS

    int n, m;
    cin >> n >> m;

    vector<vector<int>> a(n, vector<int>(m));

    for (auto& row : a)
        for (int& x : row)
            cin >> x;

WHEN: N x M numeric grid.

IMPORTANT: You do not need to care where each row’s newline occurs.

13. GRID OF CHARACTERS

    int n, m;

    vector<string> grid(n);

WHEN: Each row has no spaces between cells.

ADVANTAGE: grid[i][j] directly gives the cell.

21. READ A LINE UNTIL EOF

    string line;

    while (getline(cin, line)) {
        // process one complete line
    }

WHEN: The input is fundamentally line-oriented.

IMPORTANT: getline() preserves spaces inside the line. It removes the
newline itself.

22. TOKENIZE A LINE WITHOUT stringstream

For performance-sensitive/custom parsing:

    string s;
    getline(cin, s);

    int n = s.size();

    for (int i = 0; i < n; ) {
        while (i < n && s[i] == ' ')
            ++i;

        int x = 0;

        while (i < n && isdigit(s[i])) {
            x = x * 10 + (s[i] - '0');
            ++i;
        }

        // use x
    }

WHEN: Rarely needed. Use when parsing itself is performance-critical or
the grammar is custom.

EXPERT NOTE: Do not manually tokenize normal CP input just to look
clever. cin >> / stringstream are usually clearer.

23. COMMA / CUSTOM DELIMITERS

Example input: 10,20,30,40

Simple approach:

    string line;
    getline(cin, line);

    for (char& c : line)
        if (c == ',')
            c = ' ';

    stringstream ss(line);

    int x;
    while (ss >> x) {
        // process x
    }

WHEN: Input uses punctuation as separators.

Alternative: manually parse characters if the grammar is more complex.

27. CHAR INPUT

    char c;
    cin >> c;

WHEN: Individual non-whitespace characters.

IMPORTANT: cin >> c skips whitespace.

If you need the next raw character INCLUDING whitespace:

    char c = cin.get();

This is uncommon in ordinary CP.


= = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = = =
28. cin.get()

    char c;
    c = cin.get();

WHEN: You need exactly the next character from the stream.

Unlike operator>> for char, get() does NOT skip whitespace.

Useful for: - character-level parsers - custom grammars - detecting
newlines/spaces explicitly

Usually unnecessary for standard CP input.

29. cin.peek()

    char c = cin.peek();

WHEN: You want to inspect the next character WITHOUT consuming it.

Useful for: - custom parsers - deciding what kind of token comes next

Rare in normal CP.

30. cin.ignore(count, delimiter)

    cin.ignore(1000, '\n');

General form:

    cin.ignore(count, delimiter);

WHEN: Discard input until either: - count characters have been
discarded, OR - delimiter is encountered.

Most common:

    cin.ignore(numeric_limits<streamsize>::max(), '\n');

Meaning: “Throw away everything until the next newline.”

31. std::ws + getline()

    string s;
    getline(cin >> ws, s);

WHEN: You want to consume leading whitespace before reading a line.

Example: int n; cin >> n; getline(cin >> ws, s);

IMPORTANT: ws consumes ALL leading whitespace, potentially including
multiple newlines.

This is NOT always equivalent to ignore(…, ‘’).

Use it when leading whitespace should be ignored. Use ignore(…, ‘’) when
you specifically want to finish the current line and move to the next
line.

37. FASTEST COMMON APPROACH: DON’T OVER-PARSE

If input says:

    N
    N integers

Do:

    int n;
    cin >> n;

    vector<int> a(n);

    for (int& x : a)
        cin >> x;

NOT:

    getline()
    -> string
    -> stringstream
    -> string
    -> stoi()
    -> int

WHEN: Always prefer the direct approach when line boundaries don’t
matter.

39. COMMON ANTI-PATTERNS

AVOID:

    string x;
    cin >> x;
    int n = stoi(x);

WHEN: Input is already numeric.

USE:

    int n;
    cin >> n;

AVOID:

    getline(cin, line);
    stringstream ss(line);

WHEN: The problem simply gives N integers.

USE:

    cin >> x;

AVOID:

    cin.ignore();

WHEN: You are not certain exactly one character should be discarded.

USE:

    cin.ignore(numeric_limits<streamsize>::max(), '\n');

when your actual intention is: “discard the rest of this line.”

AVOID: manually caring about whether integers are on one line or five
lines.

USE: cin >> x;

40. THE EXPERT DECISION TREE

Question 1: Is this input fundamentally whitespace-separated tokens?

    YES -> cin >> variable

Question 2: Does the entire line have semantic meaning?

    YES -> getline()

Question 3: Do I need to parse tokens inside that line?

    YES -> getline() + stringstream

Question 4: Is the format custom enough that stringstream is
insufficient?

    YES -> manual character parsing

Question 5: Is the input known-size?

    YES -> read exactly that many values.

Question 6: Is there no count and input continues?

    YES -> while (cin >> x) / while (getline(...))

Question 7: Did I switch from cin >> to getline?

    YES -> think carefully about the leftover newline.

41. PERFORMANCE / STYLE RULES

1.  Prefer direct typed extraction:

        cin >> int_value;

2.  Don’t convert numeric input: string -> stoi -> int

    unless the string representation is actually needed.

3.  Use getline only when line boundaries matter.

4.  Use stringstream for line-local tokenization.

5.  Use ios::sync_with_stdio(false) and cin.tie(nullptr) for normal
    high-volume CP I/O.

6.  Don’t manually parse input unless the problem warrants it.

7.  Don’t optimize input parsing before knowing input size or
    encountering an actual bottleneck.

8.  Treat whitespace as insignificant when using operator>>.

9.  Treat newlines as meaningful only when the problem’s format makes
    them meaningful.

10. Read directly into the data structure whenever practical.

43. GOLDEN RULE

For CP, start with the simplest parser that matches the DATA MODEL.

    Tokens?       cin >>
    Lines?        getline()
    Tokens in line?
                  getline() + stringstream
    Weird grammar?
                  custom parser

Do not parse the presentation when the problem only cares about the
underlying sequence of values.

The most common expert CP input operation is still simply:

    cin >> x;

References: CP-Algorithms is a major competitive-programming reference.
Its problem implementations routinely use direct typed extraction for
structured input, while custom string parsing is reserved for genuinely
string-oriented problems.
